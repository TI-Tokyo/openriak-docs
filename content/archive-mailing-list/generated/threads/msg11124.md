quite small helper class to enable efficient async operation of the official
Java client. I&#x27;m calling it Riaktor (even though there&#x27;s apparently an old Ruby
gem of the same name that hasn&#x27;t been updated in several years).

<a href="https://github.com/jbrisbin/riaktor">https://github.com/jbrisbin/riaktor</a>

Since it uses Reactor, it also has OOTB Groovy love, which includes using
Closures as callbacks, etc… There&#x27;s basically no documentation yet; only what&#x27;s
in the tests. But if you&#x27;re brave enough to try out something completely new, I
would love to get your feedback! :)

I&#x27;ve load-tested this to over 150,000 ops/sec using 2 threads via
Disruptor-based RingBufferDispatchers. Reactor itself can do 15M ops/sec on my
three-year-old MacBook Pro so the bottleneck is going to be the network and
your Riak cluster. But assuming you&#x27;ve got the bandwidth to handle it, Riaktor
can push to (and pull from) Riak very efficiently.

Once you&#x27;ve got some data in the client, the idea is that you&#x27;ll want to
continue integrating with Reactor&#x27;s async tools by doing compositions (map,
filter, reduce, etc… a la RxJava Observable). That&#x27;s why Riaktor returns a
Promise for almost everything.

I&#x27;d be interested to get your feedback as it would directly feed back into
better Reactor features.

[1] - <a href="https://github.com/reactor/reactor/">https://github.com/reactor/reactor/</a>

Thanks!
