I pretty much like the Big Data patterns presented at the last re:Invent.

<a href="http://www.slideshare.net/AmazonWebServices/big-data-architectural-patterns-and-best-practices-on-aws">http://www.slideshare.net/AmazonWebServices/big-data-architectural-patterns-and-best-practices-on-aws</a>
(slide 45)
<a href="https://www.youtube.com/watch?v=RNrsIlweCno">https://www.youtube.com/watch?v=RNrsIlweCno</a>

I think Riak TS can play a key role in the &quot;store&quot; phase, Spark connector
bridges one of the gaps to &quot;process/analyze&quot; phase. Nevertheless there are
plenty of other &quot;process/analyze&quot; options beyond Spark. This includes BI
tools, machine learning tools, data warehouse tools and so on.

Many players in the market have invested heavily bridging this gap. See BI
connectors and export for Mongo (
<a href="https://www.mongodb.com/products/bi-connector">https://www.mongodb.com/products/bi-connector</a>,
<a href="https://docs.mongodb.com/manual/reference/program/mongoexport/">https://docs.mongodb.com/manual/reference/program/mongoexport/</a>). Kinesis
firehose from AWS (
<a href="https://aws.amazon.com/blogs/aws/amazon-kinesis-firehose-simple-highly-scalable-data-ingestion/">https://aws.amazon.com/blogs/aws/amazon-kinesis-firehose-simple-highly-scalable-data-ingestion/</a>
).

What&#x27;re having to do in Riak TS is developing applications to export the
data and setting up some cron jobs and monitoring in place.
