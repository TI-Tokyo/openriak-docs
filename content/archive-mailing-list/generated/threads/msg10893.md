<nav class="mailing-list-toc" aria-label="Thread contents"><h2>In this thread</h2><ol><li><a href="#msg10893"><span>Link-walking and starting object?</span><small>Tim Kientzle · Apr 15, 2013</small></a></li></ol></nav><section class="mailing-list-thread" data-thread-root="msg10893"><article id="msg10893" class="mailing-list-message mailing-list-message--root"><header class="mailing-list-message__header"><span class="mailing-list-message__author">Tim Kientzle</span><time datetime="2013-04-15T11:38:57-07:00">April 15, 2013 at 11:38 AM</time></header><div class="mailing-list-message__body">The link-walking syntax allows you to return multiple results, e.g.,

  curl <a href="http://.../riak/bucket/obj/_,key1,1/_,key2,1">http://.../riak/bucket/obj/_,key1,1/_,key2,1</a>

will follow two links and return two results.

Is there a way to have Riak also return the starting object?
(&#x27;bucket/obj&#x27; in this example)?

I&#x27;m exploring a couple of ideas for handling things like user
lookups where there&#x27;s an email object that links to the owning
account object.  If someone tries to login using their email
address, I would like to be able to look up the email directly
and have both it and the account object pulled via a link-walk.

In a similar vein, is there a practical limit on the
fan-out for link-walking?  One of the problems I&#x27;m considering
would usually have a fan-out of only one or two but might
occasionally get a fan-out of a thousand or more.
