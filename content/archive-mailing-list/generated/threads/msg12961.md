I&#x27;m assuming you&#x27;re talking about Yokozuna (Riak Search 2.0). Answers inline...

<blockquote>1. I understand that search automatically analyzes JSON, but that does
include nested JSON objects?
</blockquote>
Yes. You can POST data to the /yz/extract URL to see how your JSON (or
XML) is parsed by the extractor.

<blockquote>2. If I want to return more than just key/value pairs what options do I have
aside from using search queries as input for MapReduce jobs?
</blockquote>
When search returns data it can return values as well, depending on
the Solr schema being used. Ideally you build your schema to index and
store just the data needed by your application.

<blockquote>3. When it comes to &quot;children&quot; objects, is it better to search for objects or
rely on numerous links?
</blockquote>
I&#x27;m not sure what you mean here. Generally, child objects can be
stored either as part of their parent (nested) in a value, or as
values in another bucket. In the latter case, the parent object just
has a reference to the child&#x27;s ID (and vice-versa, if necessary). The
decisions you make when modeling your data should take access, update
and search patterns into account, since all impact the shape of the
objects you store.
