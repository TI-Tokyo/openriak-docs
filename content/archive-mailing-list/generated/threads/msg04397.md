It would probably help diagnose your problem if you specified exactly
what code you were inserting data with and what that data looks like.
That&#x27;s probably where the problem is.

I don&#x27;t know the specifics of that riak client but you can look at
what&#x27;s coming through if you run that under pdb.
<a href="http://docs.python.org/library/pdb.html">http://docs.python.org/library/pdb.html</a>

First start Python in interactive mode:
$ python -i yourscript.py

then when it prints the traceback and kicks you to the interactive
prompt you should load pdb in post-mortem mode:

<blockquote><blockquote><blockquote>import pdb; pdb.pm()
</blockquote></blockquote></blockquote>
From there you can navigate up the stack (with the &quot;up&quot; command) and
print out response[1] (with &quot;p response[1]&quot;) to see what it is. You
may want to look at the repr of response[1] to be sure it is what you
think it is.

I would play around with this using the python interpreter.  Instead of calling
my_bucket.get(key), I would use my_bucket.get_binary(key).  This will give you
the raw string stored in Riak instead of auto-decoding it.  Inspect the result;
make sure it does indeed look like valid json.  If it does, I&#x27;d run it through
the stdlib json.loads and see what happens.

<blockquote>Where do you set the application type header, are you talking about the
bucket object, the object itself or is it something that is set on the riak
server itself?
</blockquote>
It&#x27;s an attribute of the object itself.  It&#x27;s set by default to
&quot;application/json&quot; as long as you are creating standard Riak objects and not
Riak binaries.  See
<a href="http://basho.github.com/riak-python-client/tutorial.html#storing-keys-values">http://basho.github.com/riak-python-client/tutorial.html#storing-keys-values</a>
for more detail.
