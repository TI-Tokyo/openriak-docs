staging-riak001.pp /dev/sda3              15G  6.3G  7.2G  47% /
staging-riak002.pp /dev/sda3              15G  6.4G  7.1G  48% /

staging-riak006.pp /dev/sda3              15G  6.3G  7.3G  47% /

Specifically, /var/lib/riak/bitcask is using up most of that space. It
seems to have files in there that are much older than any of the other
nodes. We&#x27;ve done maintenance of various sort on this cluster -- as the
name indicates, we use it as a staging ground before we go to production. I
don&#x27;t recall a specific issue per se, but I wouldn&#x27;t rule it out.

Is there a way to figure out if there&#x27;s an underlying issue here, or
whether some of this disk space is not really current and can somehow be
purged?

What info would help answer those questions?

Make sure that the configuration on that node is not different
to the others. For example, it could be configured to never merge Bitcask
files, so that space could never be reclaimed.

</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg16139" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Charlie Voiselle</span><time datetime="2015-05-15T13:49:49-07:00">May 15, 2015 at 1:49 PM</time><span class="mailing-list-message__subject">Re: uneven disk distribution</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">Johnny:

Something else to look for would be any errors in the console.log related to
Bitcask merging.  It would be interesting to see if the unusual disk
utilization was related to a specific partition.  If it is, you could consider
removing that particular partition and running riak_kv:repair to restore the
replicas from the adjacent partitions.  I can provide more information if you
find that to be the case.
