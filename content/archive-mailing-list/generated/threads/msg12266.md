</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg12268" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Evan Vigil-McClanahan</span><time datetime="2013-09-15T10:57:04-07:00">September 15, 2013 at 10:57 AM</time><span class="mailing-list-message__subject">Re: new cluster -- riak starts and dies on each vm.</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">Riak is no longer built or tested on 32 bit machines, so that could
potentially be a problem.

This document has some recommendations on tunings for linux that can
affect the OOM killer and VM system, most notably the vm.swappiness
sysctl:
<a href="http://docs.basho.com/riak/latest/cookbooks/Linux-Performance-Tuning/">http://docs.basho.com/riak/latest/cookbooks/Linux-Performance-Tuning/</a>

It could be that leveldb by default now maps more than 4GB of virtual
memory, expecting the large virtual memory spaces of 64 bit systems
and smart VM work to use memory efficiently.  In that case, you&#x27;ll
want to tune down the number of open files for leveldb, the number
write buffer bounds, and potentially the cache size, although that&#x27;s
pretty low by default.
