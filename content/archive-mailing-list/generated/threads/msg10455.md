Scanning the code of
riak_kv_w_reduce, it looks like the culprit could be line 270, … something in
the middle of running a JS map/reduce job with an Erlang Fun object which is
incompatible across releases.

It looks like with the present 1.3.0 codebase, JS M/R will likely not work
until all the nodes have been upgraded.    Some background here:
<a href="http://www.javalimit.com/2010/05/passing-funs-to-other-erlang-nodes.html">http://www.javalimit.com/2010/05/passing-funs-to-other-erlang-nodes.html</a>

The fix going forward should be to have js_runner/1 return a symbolic
(external) fun object.  But that may not be the answer you&#x27;re looking for.

Kresten
