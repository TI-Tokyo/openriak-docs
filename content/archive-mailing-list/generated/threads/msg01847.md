Riak Recap for Dec 22 - 26

1) Sean Cribbs merged a piece of code from flippingbits that added
observers to Ripple.

Details here ---&gt; <a href="https://github.com/seancribbs/ripple/compare/baa7fec...e11b0fe">https://github.com/seancribbs/ripple/compare/baa7fec...e11b0fe</a>

&quot;riak-session-manager.&quot; It&#x27;s the beginning of a Tomcat Session Manager
backed by Riak.

Repo ---&gt; <a href="https://github.com/jbrisbin/riak-session-manager">https://github.com/jbrisbin/riak-session-manager</a>

Added to the Riak Wiki here ---&gt;

3) Chris Umbel has the beginnings of a C client for Riak available on GitHub.

Repo here ---&gt; <a href="https://github.com/chrisumbel/riakclient">https://github.com/chrisumbel/riakclient</a>

Added to the Riak Wiki here ---&gt;

<a href="https://wiki.basho.com/display/RIAK/Community-Developed+Libraries+and+Projects#Community-DevelopedLibrariesandProjects-ClientLibraries">https://wiki.basho.com/display/RIAK/Community-Developed+Libraries+and+Projects#Community-DevelopedLibrariesandProjects-ClientLibraries</a>

4) I&#x27;m not sure if there are any Web.py fans out there, but it looks
like David Hollander is going to start working on a Riak-based
&quot;skeleton user auth system.&quot;

Details here for anyone who is interested/might want to get involved
---&gt; <a href="http://groups.google.com/group/webpy/browse_thread/thread/7baad3a15882db0b">http://groups.google.com/group/webpy/browse_thread/thread/7baad3a15882db0b</a>

5) seancribbs and toflames had a short convo in #riak that started
with &quot;I would like to know if it is possible to run a mapreduce query
on the results of another mapreduce query in riak.&quot;

Gist here ---&gt; <a href="https://gist.github.com/756228">https://gist.github.com/756228</a>

6) Q --- If I use the value &quot;quorum&quot; as symbolic consistency for both
read and writes, will I get strong consistency? (from toflames via
#riak)

    A ---If by strong consistency, you mean &quot;read your writes&quot;, then yes.

&quot;Quorum&quot; is talked about in several places on the Riak Wiki:

<a href="http://wiki.basho.com/dosearchsite.action?searchQuery.queryString=ancestorIds%3A1802841+AND+Quorum&amp;searchQuery.spaceKey=RIAK">http://wiki.basho.com/dosearchsite.action?searchQuery.queryString=ancestorIds%3A1802841+AND+Quorum&amp;searchQuery.spaceKey=RIAK</a>

7) Q --- Does riak have a _changes feed like couchdb? (from hackeron via #riak)

    A --- No.

8) Q --- In regards to riak_kv_cache_backend, is the max_ttl a hard
cap? i.e., if there is an access at second 3599 will the object still
be evicted right afterwards or will it be extended for another 600s?
(from progski via #riak)

   A --- TTL is relative to last access so accessing at 3599s would
extend the lease.

think you&#x27;re incorrect.  After running a quick test I&#x27;ve witnessed the
following behavior.

1) TTL - If an object is not accessed for this amount of time it will be
evicted.
2) Max TTL- The object will be evicted (no matter what) once it has been
held by the cache for this amount of time.

The scenario I ran was to set TTL to 10s and Max TTL to 60s.  My first test
PUT an object in the cache and performed a get every 9s.  On the 7th get
(63s) it returned &quot;not found.&quot;  My second test did the same thing but slept
for 15s before performing the first GET and it returned &quot;not found.&quot;

Therefore, it does indeed look like Max TTL is a hard cap.
