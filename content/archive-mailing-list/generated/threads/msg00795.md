</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg00799" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Kevin Smith</span><time datetime="2010-07-29T04:02:02-07:00">July 29, 2010 at 4:02 AM</time><span class="mailing-list-message__subject">Re: JSON lib for erlang</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">mochijson2 is what I tell anyone who asks to use. Representing strings as
binaries avoids a whole host of data mangling problems when you have to deal
with non-ASCII or non- ISO-8859 character sets. Strings as binaries also frees
up lists to be interpreted as JSON arrays. This simplifies the data
representation since the only annotation you have to provide is on hashes aka
structs:

{struct, [{username, &lt;&lt;&quot;jdoe&quot;&gt;&gt;}, {first_name, &lt;&lt;&quot;John&quot;&gt;&gt;}, {last_name,
&lt;&lt;&quot;Doe&quot;&gt;&gt;}]}

translates to:

{&quot;username&quot;: &quot;jdoe&quot;,
 &quot;first_name&quot;: &quot;John&quot;,
 &quot;last_name&quot;: &quot;Doe&quot;}

mochijson requires, if I remember correctly, annotations for both arrays and
structs which is more &quot;noisy&quot; when you&#x27;re doing lots of encoding and decoding.
