   - Is _version_ required?
   - I see SolrCloud mentioned in some documentation (see below)? Does Riak

   - How does Riak Search handle optimistic locking?

P.S. Per <a href="https://wiki.apache.org/solr/SchemaXml">https://wiki.apache.org/solr/SchemaXml</a>
Recommended fields

While these fields aren&#x27;t strictly mandatory (Solr will run if you remove
them fully), Bad Things happen in some situations if they aren&#x27;t defined.
We recommend that you leave these fields alone. If you don&#x27;t use them,
there&#x27;s no appreciable penalty.

   -

   id - Almost all Solr installations have this field defined as the
   &lt;uniqueKey&gt; (see below).
   -

   _version_ [image: &lt;!&gt;] Solr4.0 &lt;<a href="https://wiki.apache.org/solr/Solr4.0">https://wiki.apache.org/solr/Solr4.0</a>&gt; -
   This field is used for optimistic locking in SolrCloud
   &lt;<a href="http://wiki.apache.org/solr/SolrCloud">http://wiki.apache.org/solr/SolrCloud</a>&gt; and it enables Real Time Get
   &lt;<a href="http://wiki.apache.org/solr/RealTimeGet">http://wiki.apache.org/solr/RealTimeGet</a>&gt;. If you remove it you must
   also remove the transaction logging from solrconfig.xml, see Real Time
   Get &lt;<a href="http://wiki.apache.org/solr/RealTimeGet">http://wiki.apache.org/solr/RealTimeGet</a>&gt;.

<blockquote>Is _version_ required?
</blockquote>
It should not be required as the documentation says it is only needed for
real-time GET which Riak Search (Yokozuna) disables since Riak KV provides the
get/put implementation.
<blockquote>I see SolrCloud mentioned in some documentation (see below)? Does Riak Search
use it?
</blockquote>
RS does not make use of SolrCloud at all.  It uses Solr’s Distributed Search
but that is something that existed well before SolrCloud.  All routing and
replica administration is handled by Riak.  Each Solr instance (one per node)
has no awareness of the other nodes except for the explicit distributed queries
sent by Riak.

<blockquote>How does Riak Search handle optimistic locking?
</blockquote>
It doesn’t use Solr’s optimistic locking at all.  All key-value semantics come
from Riak itself.  RS simply indexes an object’s values.
<blockquote>See this comment on the default_schema.xml on Github:
&lt;!-- TODO: is this needed? --&gt;
&lt;field name=&quot;_version_&quot; type=&quot;long&quot; indexed=&quot;true&quot; stored=&quot;true&quot;/&gt;
<a href="https://raw.githubusercontent.com/basho/yokozuna/develop/priv/default_schema.xml">https://raw.githubusercontent.com/basho/yokozuna/develop/priv/default_schema.xml</a>
</blockquote>
Yes, I wrote that TODO.  It is one of many that founds its way into 2.0.0 :).
You should run fine without this field if you create a custom schema.

<blockquote>P.S. Per <a href="https://wiki.apache.org/solr/SchemaXml">https://wiki.apache.org/solr/SchemaXml</a>
_version_  Solr4.0 - This field is used for optimistic locking in SolrCloud
and it enables Real Time Get. If you remove it you must also remove the
transaction logging from solrconfig.xml, see Real Time Get.
</blockquote>
Just to reiterate what I said above, RS disables the transaction logging and
thus there is no real time get.  There is no reason for it since that is what
Riak itself provides.
