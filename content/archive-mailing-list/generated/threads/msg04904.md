structured hash trees. When an &quot;update&quot; occurs, a new copy of the data is
written. Eventually, during a compaction process, the dead records are cleaned
up. There are rules for how often compactions run. You can change some of those
settings for Riak Search:
<a href="http://wiki.basho.com/Riak-Search---Operations-and-Troubleshooting.html">http://wiki.basho.com/Riak-Search---Operations-and-Troubleshooting.html</a>

You can think of this as being similar to the ghost record clean up/vacuum
process that runs in your favorite RDMBS (as long as that RDBMS implements some
form of MVCC).

I take it you are using the default backend, bitcask?  If so you should know
it&#x27;s an append only log format that is periodically merged.  So until a
merge is triggered the data will only grow.  Even if you delete objects it
still grows as a delete is actually just a special tombstone msg added to
the log.

You can read more about bitcask configuration here:
<a href="http://wiki.basho.com/Bitcask.html">http://wiki.basho.com/Bitcask.html</a>

-Ryan
