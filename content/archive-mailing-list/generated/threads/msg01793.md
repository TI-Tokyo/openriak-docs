</blockquote>R and W are guaranteed reads and writes with a response from the node in the
cluster. There&#x27;s some info in the wiki, but it took me a second to find it:
<a href="http://wiki.basho.com/display/RIAK/Tunable+CAP+Controls+in+Riak#TunableCAPControlsinRiak-WValueandWriteFaultTolerance">http://wiki.basho.com/display/RIAK/Tunable+CAP+Controls+in+Riak#TunableCAPControlsinRiak-WValueandWriteFaultTolerance</a>

If your W is less than N, you&#x27;ve still told Riak that you want N copies of
the data, but you only care that W nodes responded that the write was
successful. Hopefully that data will get to the other nodes in time, but if
it doesn&#x27;t then there are mechanisms in place to make sure that it does.
Check out the Replication &lt;<a href="http://wiki.basho.com/display/RIAK/Replication">http://wiki.basho.com/display/RIAK/Replication</a>&gt; page
as well as the Hinted
Handoff&lt;<a href="http://wiki.basho.com/display/RIAK/Riak+Glossary#RiakGlossary-HintedHandoff">http://wiki.basho.com/display/RIAK/Riak+Glossary#RiakGlossary-HintedHandoff</a>&gt;
for
more info.

The client connects to Riak and issues a write request. Riak then issues
write requests to N nodes and waits for W of them to respond before it tells
the client that the write succeeded.
