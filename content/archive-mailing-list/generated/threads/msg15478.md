</blockquote>
You can add whatever jar files you&#x27;d like to the appropriate place. On
Debian-based distros, the WEB-INF/lib directory for Solr is located
here:

/usr/lib/riak/lib/yokozuna-2.0.0-1-g6ac3a63/priv/solr/solr-webapp/webapp/WEB-INF/lib

<blockquote>Is it possible to upgrade the Solr instance to a newer version?
</blockquote>
There is no way at this time, other than to fork the yokozuna
repository and make/test all the necessary changes and build your own
custom Riak version.

<blockquote>And how the search itself occurs? We query riak and riak will query each

</div></div></details></li><li class="mailing-list-reply"><details id="msg15481" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Sean Cribbs</span><time datetime="2015-01-13T08:22:00-08:00">January 13, 2015 at 8:22 AM</time><span class="mailing-list-message__subject">Re: Raik 2.0.4 - Solr version</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">The version of Solr bundled with Riak 2.0.4 is 4.7.0.

I&#x27;m not sure what process would be required to bundle tokenizers and
analyzers, but I suspect it would be similar to how you deploy them with
stock Solr. Some tweaks may need to be made to load customizations.

You cannot upgrade the Solr version by itself because we build a small
amount of custom code into Solr and we want to validate each upgrade before
shipping it. Since it uses some Solr-internal interfaces, we can&#x27;t
guarantee that our customizations won&#x27;t break on upgrade.

The search is &quot;planned&quot; on the Riak side (which shards/cores to query, etc)
but executed by Distributed Solr. Search performance is good; Ryan Zezeski
benchmarked it extensively in its initial development. However, the primary
benefit of using Riak&#x27;s Solr integration is the automatic synchronization
of your key-value data with the search indexes. As key-value data gets
written, handed off, or repaired, your search index is automatically kept
up-to-date via the same mechanism that keeps individual replicas of the
originals in sync.
