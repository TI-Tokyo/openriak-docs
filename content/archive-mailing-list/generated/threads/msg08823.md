    Indeed this is a very annoying Erlang behaviour, especially when
running in container environments or highly controlled / automated
ones.

    If you are interested in finding more about both the &quot;details&quot; and
possible hacks, please see my previous posts (both here and on Erlang
mailing list):
    <a href="http://lists.freedesktop.org/archives/systemd-devel/2012-August/006273.html">http://lists.freedesktop.org/archives/systemd-devel/2012-August/006273.html</a>

<a href="http://lists.basho.com/pipermail/riak-users_lists.basho.com/2012-June/008608.html">http://lists.basho.com/pipermail/riak-users_lists.basho.com/2012-June/008608.html</a>
    <a href="http://erlang.org/pipermail/erlang-questions/2011-October/062004.html">http://erlang.org/pipermail/erlang-questions/2011-October/062004.html</a>
    <a href="http://erlang.org/pipermail/erlang-questions/2011-October/061893.html">http://erlang.org/pipermail/erlang-questions/2011-October/061893.html</a>

    In short the solution is:
    * trick the erlang process not to start epmd itself; (see the last
link above;)
    * run epmd yourself as a separate service;

    Ciprian.

It should be trivial to add that to &#x27;riak stop&#x27; if you indeed want that.
