<nav class="mailing-list-toc" aria-label="Thread contents"><h2>In this thread</h2><ol><li><a href="#msg03350"><span>Mapreduce crosstalk</span><small>Aphyr · May 17, 2011</small></a><ol><li><a href="#msg03396"><span>Re: Mapreduce crosstalk</span><small>Kelly McLaughlin · May 24, 2011</small></a></li></ol></li></ol></nav><section class="mailing-list-thread" data-thread-root="msg03350"><article id="msg03350" class="mailing-list-message mailing-list-message--root"><header class="mailing-list-message__header"><span class="mailing-list-message__author">Aphyr</span><time datetime="2011-05-17T12:35:20-07:00">May 17, 2011 at 12:35 PM</time></header><div class="mailing-list-message__body">I was writing a new mapreduce query to look at users over time, and ran
it over a single user in production. After that, other mapreduce jobs
over users started returning results from my new map phase, some of the
time. After five minutes of this, I had to restart every node in the
cluster to get it to stop.

Every node has {map_cache_size, 0} in riak_kv.

The map phase that screwed things up was:

function(v) {
  o = JSON.parse(v.values[0].data);

  // Age of account in days
  age = Math.round(
    (Date.now() - Date.iso8601(o.created_at)) /
    (1000 * 60 * 60 * 24)
  );

  return [[&#x27;t_user_scores&#x27;, v.key, age]];
}

It looks like one node started running that phase instead of the
requested phase for subsequent jobs. It *should* have run this one, but
didn&#x27;t.

function(v) {
        o = JSON.parse(v.values[0].data);
        return [{
                key: v.key,
                name: o.name,
                thumbnail: o.thumbnail
        }];
}

Now I&#x27;m scared to run MR jobs. Could it be an issue with returning
keydata? Anybody else seen this before?

--Kyle
