into RabbitMQ as a plugin. I already have a consumer that invokes vnodes but
I&#x27;m wondering (in code) whether or not it would be more efficient to implement
this behaviour as a custom exchange. This is also an exercise for my Erlang
Factory presentation.

To that end, I&#x27;ve got riak_core running as a plugin with a special script I
call from my Makefile to patch the riak_core distro so it will go into
RabbitMQ&#x27;s VM without complaining about extra .beam files (for things already
inside RabbitMQ).

I&#x27;m getting a couple warnings related to cluster_info and riak_err not being
available. I&#x27;ve included cluster_info to get rid of that warning, but I&#x27;m not
sure I want to include riak_err because it seems to put my logging output back
into the console (I run my RabbitMQ broker in a terminal so I can get an Erlang
shell with it). It makes a mess in my terminal window, so I&#x27;m considering
leaving that out of my plugins directory.

Will leaving riak_err out cause problems with riak_core? Other than this,
riak_core was relatively easy to embed.
