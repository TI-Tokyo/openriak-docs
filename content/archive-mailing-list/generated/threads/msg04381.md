</blockquote></blockquote></div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg04452" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Jeremiah Peschka</span><time datetime="2011-08-24T09:50:49-07:00">August 24, 2011 at 9:50 AM</time><span class="mailing-list-message__subject">Re: Setting up a Riak + Mongrel2 Stack</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">Use whatever language on the server-side that you&#x27;re comfortable working with.
If you&#x27;re into Ruby, Ripple is quite mature. The Java client is nice. I
personally like the .NET client (of course I&#x27;m slightly biased on that front).
I&#x27;d avoid exposing Riak to the open internet, even if it is through a proxy of
some sort. Use a set of APIs so that you can abstract your data storage away
from the calling application. A lot of people are reporting success with
haproxy as the proxy for their Riak instances.

OJ Reeves put together a bit of a tutorial on haproxy and Riak:
<a href="http://buffered.io/2010/09/12/webmachine-erlydtl-and-riak-part-2/">http://buffered.io/2010/09/12/webmachine-erlydtl-and-riak-part-2/</a>

You can drastically improve performance by avoiding the HTTP interface and
using the Protocol Buffers interfaces to Riak, but that depends more on your
language of choice than anything else (some libraries may not support the PB
interface).
