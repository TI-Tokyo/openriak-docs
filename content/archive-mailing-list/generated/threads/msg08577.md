<nav class="mailing-list-toc" aria-label="Thread contents"><h2>In this thread</h2><ol><li><a href="#msg08577"><span>What ever happened to delete support for post-commit hooks?</span><small>David Goehrig · Sep 17, 2012</small></a><ol><li><a href="#msg08580"><span>Re: What ever happened to delete support for post-commit hooks?</span><small>Jon Meredith · Sep 17, 2012</small></a><ol><li><a href="#msg08586"><span>Re: What ever happened to delete support for post-commit hooks?</span><small>David Goehrig · Sep 18, 2012</small></a></li></ol></li></ol></li></ol></nav><section class="mailing-list-thread" data-thread-root="msg08577"><article id="msg08577" class="mailing-list-message mailing-list-message--root"><header class="mailing-list-message__header"><span class="mailing-list-message__author">David Goehrig</span><time datetime="2012-09-17T11:52:41-07:00">September 17, 2012 at 11:52 AM</time></header><div class="mailing-list-message__body">Many moons ago (circa 0.14.0) when you did a curl -X DELETE to a riak
bucket with a post commit hook it would be invoked and you could use the
X-Riak-Deleted tag to process the file.  I have just such a post commit
hook running on on a 0.14.0 build.

We recently looked at upgrading to 1.2, but discovered that our post commit
hooks were no longer being fired at all on DELETE, only POST and PUT.
 Looking through the offending bits of the code, it looks like the entire
hook invocation subsystem was rewritten since 0.14.0, but the documentation
wiki: <a href="http://wiki.basho.com/Commit-Hooks.html#Post-Commit-Hooks">http://wiki.basho.com/Commit-Hooks.html#Post-Commit-Hooks</a>

Still states that:

As with pre-commit hooks, deletes are considered writes so post-commit hook
functions will need to inspect object metadata for the presence of *
X-Riak-Deleted* to determine when a delete has occurred.

Any idea why this would no longer be true?

Dave

</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg08586" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">David Goehrig</span><time datetime="2012-09-18T12:26:17-07:00">September 18, 2012 at 12:26 PM</time><span class="mailing-list-message__subject">Re: What ever happened to delete support for post-commit hooks?</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">I discovered what the behavior change is and it was subtle…

Suppose you populated a value in the bucket:

        curl -X PUT <a href="http://localhost:8098/riak/test/foobar">http://localhost:8098/riak/test/foobar</a> -d &#x27;{&quot;foo&quot;:&quot;bar&quot;}&#x27;

In the 0.14.0 release if you did a curl -X DELETE
<a href="http://localhost:8098/riak/test/foobar">http://localhost:8098/riak/test/foobar</a>  you could do:

        ObjectJSON = riak_object:get_value(Object),
        O = mochijson2:decode(ObjectJSON),

you would get ObjectJSON with the contents of the deleted object:

        ObjectJSON = &lt;&lt;&quot;{&quot;foo&quot;:&quot;bar&quot;}&quot;&gt;&gt;
        O = {struct,[{&lt;&lt;&quot;foo&quot;&gt;&gt;,&lt;&lt;&quot;bar&quot;&gt;&gt;}]}

In 1.2, if you did the same thing, however, you&#x27;d get the following:

        ObjectJSON = &lt;&lt;&gt;&gt;

And mochijson2:decode will blow up trying to decode the empty object

        ** exception error: no match of right hand side value any
             in function  mochijson2:tokenize/2 (src/mochijson2.erl, line 556)
             in call from mochijson2:decode1/2 (src/mochijson2.erl, line 312)
             in call from mochijson2:json_decode/2 (src/mochijson2.erl, line
307)

So while the documentation is technically true, the behavior on the post-commit
hook changed substantially in the case of DELETE.

In our hook&#x27;s case, this change was very significant as we were inspecting the
contents of the deleted object to update cache objects in other buckets.

It definitely makes life more difficult not knowing the contents of the deleted
object :)

Dave
