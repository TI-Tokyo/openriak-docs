Ken -

Riak contains its own implementation of a MapReduce API. This API is written
</blockquote>in Erlang and C and shares no code with Hadoop. We have, on occasion, described
our API as &quot;Hadoop like&quot; to help people understand the differences between our
implementation and others. For example:
<blockquote>
* CouchDB&#x27;s MapReduce incrementally builds a BTree thru the execution of
</blockquote>views. Riak doesn&#x27;t cache or store MapReduce results. Each job executes &quot;from
scratch&quot; and returns results to caller. It is up to the caller to cache or
store these results if needed.
<blockquote>
* Hadoop MapReduce jobs use HDFS or HDFS-adapted resources. Riak MapReduce
</blockquote>jobs use data stored in a Riak cluster.
<blockquote>
* Riak MapReduce jobs take advantage of their execution environment. Map
</blockquote>functions exploit data locality. This means map functions are sent to the node
hosting the required data rather than streaming the data to a central
coordinating node. The most recent version of Riak also includes improvements
which has significantly boosted the efficiency of mapping over entire buckets
of data.
<blockquote>
* Riak supports writing MapReduce functions in two languages: Erlang and
</blockquote>Javascript. Erlang is the absolute fastest, in terms of raw speed, but
Javascript runs a close second and is easier for most people to use.
<blockquote>
Depending on what your jobs are doing and which language, Erlang or
</blockquote>Javascript, there are a few tunable parameters we can tweak to improve
performance. More information about what your job is doing, how your cluster is
set up, and the kinds of performance you&#x27;re seeing would help us debug the
situation.
<blockquote>
--Kevin

Bryan,

That should only be an issue if you are putting the source of the function
</blockquote>directly in your query.  Instead, try saving the function in a bucket/key and
refer to it that way. Here&#x27;s what a phase using bucket/key instead of source
would look like:
<blockquote>
{&quot;map&quot;:{&quot;language&quot;:&quot;javascript&quot;,&quot;bucket&quot;:&quot;customMR&quot;,&quot;key&quot;:&quot;
</blockquote>extractSomeFields&quot;,&quot;keep&quot;:false}}
<blockquote>
You can use curl or any one of the the language-specific clients to store the
</blockquote>function, just specify &quot;application/javascript&quot; as the content-type.
<blockquote>
I use this technique in the &quot;yakriak&quot; demo app: <a href="http://github">http://github</a>.
</blockquote>com/seancribbs/yakriak
