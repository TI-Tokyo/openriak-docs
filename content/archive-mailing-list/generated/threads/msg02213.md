Thx in advance for any help.

1) From the basho download page, <a href="http://downloads.basho.com/innostore/">http://downloads.basho.com/innostore/</a>,
innostore is currently at release 1.0.2.  Since innostore is an embedded
version
of innodb, is there any correlation between the innostore release and the real
innodb release?  Are the features available with innodb 1.0.2 available in
innostore 1.0.2 or is there no relationship?

2)  Related to the prior question is if there is no relationship, does anyone
know of any detail documentation besides the basho wiki that shows all the
supported features and/or parameters that each version of innostore supports?
For example, does innostore support the innodb parameters:
a.            file_per_table
b.            autoextend_increment
c.             autoinc_lock_mode
d.            data_file_path

3) Is there a lot of write activity in the ring_state_dir?  I am assuming their
isn&#x27;t since the state of the node shouldn&#x27;t change that frequently but wanted a
confirmation.

Thx,
Jackson

<blockquote>2)  Related to the prior question is if there is no relationship, does

You can see the full set of config options on line 385 in this file:
<a href="https://github.com/basho/innostore/blob/master/src/innostore.erl">https://github.com/basho/innostore/blob/master/src/innostore.erl</a>

Not all the options are necessarily enabled/responsive to external
settings -- embedded inno is a bit of a finicky beast about that
stuff.

<blockquote>a.            file_per_table
</blockquote>
The setting is available, but I believe embedded inno requires this
mode -- I&#x27;ve not tried changing it.

<blockquote>b.            autoextend_increment

c.             autoinc_lock_mode
</blockquote>
I&#x27;ve not tried either of these settings, but within the scope of Riak,
they would not really be that helpful (since everything stored is just
key/value).

<blockquote>d.            data_file_path
</blockquote>
I&#x27;ve not tried this one -- typically we use data_home_dir and
log_group_home_dir to control where data/logs go.

<blockquote>3) Is there a lot of write activity in the ring_state_dir?  I am assuming
their isn&#x27;t since the state of the node shouldn&#x27;t change that frequently but
wanted a confirmation.
</blockquote>
No, there should not be a lot of write activity in ring_state_dir.

D.
