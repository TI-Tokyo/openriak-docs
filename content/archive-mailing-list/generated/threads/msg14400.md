<blockquote>Hi there,

Can somebody help me understand a bit better the bucket quorums? I will
use the Python API to write code examples:

Imagine we are building a web app like twitter, and we want fast read
(although not need to be consistent) and safe writings, this R/W
combination is appropriate?

bucket = client.bucket(&#x27;twits&#x27;)

bucket.r = 1
bucket.w = 3

# OR

bucket.set_property(&#x27;r&#x27;, 1)
bucket.set_property(&#x27;w&#x27;, 3)

Which method is better to use? or are just exactly the same?

</blockquote>The pseudo-properties in the first example are exactly the same as the
set_property() calls in the second, just a convenience. Generally I
wouldn&#x27;t recommend W=3 because it will tend to create false negatives under
heavy load, W=2 (the default) should be sufficient. Keep in mind that R=1
with notfound_ok = true (the default) can tend to result in false negative
responses as well.

<blockquote>Imagine that in this new case, we want to focus on writing fast (normally
we will write more &quot;twits&quot; than read them)... which would be the most
appropriate/suggested quorums?

Also, what&#x27;s really the difference between &quot;r&quot; and &quot;pr&quot;? what is a
&quot;primary replica&quot;?

</blockquote>Primaries are the replicas (nodes) that are the canonical owners the data,
but Riak will let you read and write even if they are not available. If
they are not available, fallback replicas (non-owner nodes) will take over
in their place. Setting PR or PW &gt; 0 will result in failures if that many
primaries are not available (the node is down or partitioned from the node
that receives the request).

<blockquote>If i set up bucket.w = 1, it will still do the 3 copies (n_val) in the
background but will reply &quot;true&quot; once 1 copy is saved, right?

</blockquote>Yes. Keep in mind W is a fast-path response, i.e. &quot;I received the request
to write&quot;, whereas DW is a &quot;I saved the key to the storage engine&quot;. There
is no practical reason for DW ever to be 0, in fact I think it is
disallowed (or silently upgraded to 1).

</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg14409" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Sean Cribbs</span><time datetime="2014-06-29T12:29:08-07:00">June 29, 2014 at 12:29 PM</time><span class="mailing-list-message__subject">Re: Help on bucket quorums</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">Roughly. Even with PR/PW you can&#x27;t say strong _consistency_, but you can
reason about stronger _durability_ and reduced divergence. To truly get
strong consistency, you have to use a consensus algorithm like Paxos, Raft,
etc. Riak 2.0 will have one that you can turn on per-bucket-type.

Generally it is best to use N/2 + 1 (&quot;quorum&quot;) for R / W unless you
absolutely know what you&#x27;re doing. See
<a href="https://www.youtube.com/watch?v=FOQVWdG5e2s">https://www.youtube.com/watch?v=FOQVWdG5e2s</a> for a great use-case of R=1
along with other bucket/request properties.
