</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg12599" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Jeremiah Peschka</span><time datetime="2013-10-10T20:14:54-07:00">October 10, 2013 at 8:14 PM</time><span class="mailing-list-message__subject">Re: Corrugated Iron for Riak- WCF Performance Issue</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">I think you may be running into some issues from your Riak cluster size.
The Basho recommendation for a Riak cluster [1] is a minimum 5 servers with
4GB of RAM and multi-core CPUs.

Before anything else, though, I recommend running basho_bench to see what
kind of numbers you get from your cluster. For reference - I can get about
1500 operations / second with single digits of latency on a 5 node Riak
cluster running on a 2012 Retina MacBook Pro. Alex Rice recently posted
some numbers for a 5 node cluster running in Azure [2] where he was able to
sustain 400 operations / second with &lt; 50ms of latency.

I&#x27;m able to get similar numbers to basho_bench using our CorrugatedIron
stress tests - can you verify the performance of both Riak using
basho_bench as well as grabbing some metrics from your WCF code? You can
instrument it using metrics-net [3] which you can also download from NuGet
[4]

[1]:
<a href="http://docs.basho.com/riak/latest/ops/building/planning/system-planning/#Hardware">http://docs.basho.com/riak/latest/ops/building/planning/system-planning/#Hardware</a>
[2]: <a href="http://markmail.org/message/nsr2an6ztwcjtopb">http://markmail.org/message/nsr2an6ztwcjtopb</a>
[3]: <a href="https://github.com/danielcrenna/metrics-net">https://github.com/danielcrenna/metrics-net</a>
[4]: <a href="http://www.nuget.org/packages/Metrics">http://www.nuget.org/packages/Metrics</a>
