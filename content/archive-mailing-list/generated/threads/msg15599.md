We are using Solr indexes on top of Riak keys to make the search more
easier.

One of the doubts regarding Solr is rebuilding the indexes. That could
happen when we want to add a new index to the schema - which would mean
drop and recreate the indexes.

As far as we know after dropping and recreating the Solr indexes, for the
already existing keys in Riak thos indexes don&#x27;t rebuild. Is there a way to
rebuild indexes on already existing keys when recreating a Solr index?

Also, if that&#x27;s possible, any idea how time costly that&#x27;d be? Let&#x27;s take
example rebuilding indexes for 100 million riak keys.

Another doubt is around corrupting Solr indexes? How &quot;probable&quot; is it? Same
question as before.. in the case of a corrupted index, how easy would be to
re-index 100 million keys?

Thanks in advance.

Hi all,

We are using Solr indexes on top of Riak keys to make the search more easier.
</blockquote>
Just to clarify, are you using Riak Search (aka, Yokozuna), or are you managing
Solr separately? I’m assuming the former.

<blockquote>One of the doubts regarding Solr is rebuilding the indexes. That could happen
when we want to add a new index to the schema - which would mean drop and
recreate the indexes.
</blockquote>
Do you mean adding a new field to the schema? You have a few options after
updating the schemas.

1) Create a new index and reattach, as you suggested
2) Rewrite Riak values inline, which will cause them to re-index
3) Delete the index directories on every node and let AAE rebuild them

There’s some new code that will create a 4th option
<a href="https://github.com/basho/yokozuna/pull/427">https://github.com/basho/yokozuna/pull/427</a>
&lt;<a href="https://github.com/basho/yokozuna/pull/427">https://github.com/basho/yokozuna/pull/427</a>&gt;

4) update the schema and let AAE fix the index

Then, we&#x27;re working on a 5th option:

5) modify schemas via command-line, and start an inline, eventually consistent
index update

There is an existing discussion on this topic:

<a href="http://comments.gmane.org/gmane.comp.db.riak.user/15420">http://comments.gmane.org/gmane.comp.db.riak.user/15420</a>
&lt;<a href="http://comments.gmane.org/gmane.comp.db.riak.user/15420">http://comments.gmane.org/gmane.comp.db.riak.user/15420</a>&gt;

<blockquote>As far as we know after dropping and recreating the Solr indexes, for the
already existing keys in Riak thos indexes don&#x27;t rebuild. Is there a way to
rebuild indexes on already existing keys when recreating a Solr index?
</blockquote>
See above.

<blockquote>Also, if that&#x27;s possible, any idea how time costly that&#x27;d be? Let&#x27;s take
example rebuilding indexes for 100 million riak keys.
</blockquote>
This is hard to say. Depending on the number of nodes, hardware, bandwidth,
object size, etc. If they’re small objects, it could be a few minutes.

<blockquote>Another doubt is around corrupting Solr indexes? How &quot;probable&quot; is it? Same
question as before.. in the case of a corrupted index, how easy would be to
re-index 100 million keys?
</blockquote>
You shouldn’t need re-index anything. If values in an index are corrupted, the
AAE (active anti-entropy) service will repair the values automatically.

<blockquote>Thanks in advance.
