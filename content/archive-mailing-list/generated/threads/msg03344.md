We&#x27;ve looked at upgrading to JaegerMonkey, but haven&#x27;t yet gotten a build that
works properly on Solaris (and SPARC), which some of our customers require.  I
personally have not followed its development and so I don&#x27;t know if there&#x27;s a
profile that works on SPARC yet.

Although upgrading to Jaeger would be a big help, I&#x27;m more concerned about the
bottleneck of converting everything to JSON before it is sent into JS -- which
also presents problems when you have binary data that is not coercible into
UTF-8.  There is at least one bug where the JSON-encoding issue is discussed,
but we recently marked it dormant because of the lack of simple solutions:
<a href="https://issues.basho.com/show_bug.cgi?id=1046">https://issues.basho.com/show_bug.cgi?id=1046</a>

Have you gotten any attention from the Mozilla people about the Solaris
issue?  They seem pretty eager to have their JS engine running in as many
places as they can.

It&#x27;s more than a little disappointing that JavaScript is touted as a
friendly and convenient way to query and transform data in Riak, but for the
kind of data sizes that would have someone use Riak in the first place,
JavaScript is really slow.  So far I keep hearing, &quot;Well, it&#x27;ll be a lot
faster and easier to just do it in Erlang.&quot;  Obviously there will be some
cost for the convenience writing code in a language other than Erlang, but
the cost seems pretty high at the moment to me.
