Riak Recap for Feb. 18 - 22

1) Sean Cribbs and several Ripple users held a call to discuss the
direction for some querying enhancements coming to Ripple.  Sean
updated the Issues on GitHub to reflect the coming changes.

* All the goodies are here ---&gt;
<a href="https://github.com/seancribbs/ripple/issues/labels/querying">https://github.com/seancribbs/ripple/issues/labels/querying</a>

2) KevBurnsJr (@KevBurnsJr) has been putting in some serious PHP-related work.

* He&#x27;s submitted four pull requests over the last several days (which
we are working on merging) -
<a href="https://github.com/basho/riak-php-client/pulls">https://github.com/basho/riak-php-client/pulls</a>

* He&#x27;s started work on porting Ripple to PHP. See:

<a href="https://github.com/KevBurnsJr/ripple-php">https://github.com/KevBurnsJr/ripple-php</a>
<a href="http://ripple-php.hackyhack.net/test/">http://ripple-php.hackyhack.net/test/</a>
<a href="http://ripple-php.hackyhack.net/docs/">http://ripple-php.hackyhack.net/docs/</a>

* Additionally, he wrote a blog post (complete with a screen cast)
called &quot;Self-descriptive hypermedia in Riak.&quot; Read/Watch here ---&gt;
<a href="http://blog.kevburnsjr.com/self-descriptive-hypermedia-in-riak">http://blog.kevburnsjr.com/self-descriptive-hypermedia-in-riak</a>

Thanks, Kev.

3) We merged some code into Luwak from Ryan Zezeski related to default
block size configuration.

* Details here ---&gt;
<a href="https://github.com/basho/luwak/commit/a516abbe1956e74721c3d0bb8434b1b9d1cf0d8a">https://github.com/basho/luwak/commit/a516abbe1956e74721c3d0bb8434b1b9d1cf0d8a</a>

Thanks, Ryan.

4) We merged in a small change to Luke contributed by Peter Lemenkov.

* Commit here ---&gt;
<a href="https://github.com/basho/luke/commit/dc5a2efc9a52de9e8357497d942babc9526aa0c8">https://github.com/basho/luke/commit/dc5a2efc9a52de9e8357497d942babc9526aa0c8</a>

Thanks, Peter.

5) There is some new code in Riak Function Contrib courtesy of Kyle
Kingsbury (@aphry).

* Details here ---&gt; <a href="http://contrib.basho.com/iso8601.html">http://contrib.basho.com/iso8601.html</a>

Thanks, Kyle.

6) Michael Ossareh released &quot;ring-session-riak,&quot; A Riak implementation
for Ring Session. This one should be of particular interest to any
Clojure fans out there.

* Code here on GitHub ---&gt; <a href="https://github.com/ossareh/ring-session-riak">https://github.com/ossareh/ring-session-riak</a>

* Another repo that might be worth keeping an eye on is his fork of
Mark McGranaghan&#x27;s Clojure bindings ---&gt;
<a href="https://github.com/ossareh/clj-riak">https://github.com/ossareh/clj-riak</a>

7) The official careers page is live on basho.com.

* Check it out here ---&gt; <a href="http://www.basho.com/company_careers.php">http://www.basho.com/company_careers.php</a>

8) Mathias Meyer (@roidrage) just announced he&#x27;ll be giving a talk
called &quot;Redis, Riak, Cassandra - The Holy NoSQL Trinity&quot; at
RailsWayCon in May.

* Read this and then mark your calendars ---&gt;
<a href="http://railswaycon.com/2011/sessions/#session-17858">http://railswaycon.com/2011/sessions/#session-17858</a>

9) Tim Dysinger (@dysinger) has been working on some Lisp Flavored
Erlang (LFE) MapReduce code for Riak, and he posted his initial code
to GitHub over the weekend.

* Repo here ---&gt; <a href="https://github.com/dysinger/gutenberg/">https://github.com/dysinger/gutenberg/</a>

Thanks, Tim.

10) We merged some code from Russell Brown (@russelldb) for the Java
Client that increases the number or concurrent connections one can
have.

* Details here ---&gt;
<a href="https://github.com/basho/riak-java-client/commit/af744212a76dac59e1dc931d9b5d5f63f5d95e14">https://github.com/basho/riak-java-client/commit/af744212a76dac59e1dc931d9b5d5f63f5d95e14</a>

Thanks, Russell.

11) Runar Jordahl wrote a blog post called &quot;Storing Part of Riak
Object Value in Memory.&quot;

* Read here ---&gt;
<a href="http://blog.epigent.com/2011/02/storing-part-of-riak-object-value-in.html">http://blog.epigent.com/2011/02/storing-part-of-riak-object-value-in.html</a>
