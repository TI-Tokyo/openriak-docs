you&#x27;re indeed hitting a JSON encoding problem here. BERT is binary data, and
won&#x27;t make the JSON parser happy when trying to deserialize it, before handing
it into the map phase. You have two options here, and none of them will involve
JavaScript as the MapReduce language.

1.) Use the Protobuff API, use Erlang functions to return the value or object
(e.g. riak_mapreduce:map_object_value or riak_kv_mapreduce:map_identity), and
then run MapReduce queries with the content type &#x27;application/x-erlang-binary&#x27;.
However, you&#x27;re constrained by client libraries here, e.g. Ruby and Python
don&#x27;t support this content type for MapReduce on the Protobuffs interface yet,
so you&#x27;d either implement something custom, or resort to a client that does,
riak-erlang-client comes to mind, though it was proven to be possible using the
Java client too, thanks to Russell. See [1] and [2]

2.) Convert the result from BERT into a JSON-parseable structure inside an
Erlang map function, before it&#x27;s returned to the client.

The second approach certainly is less restrictive in terms of API usage, but
certainly involves some overhead inside of the MapReduce request itself, but is
less prone to encoding/decoding issues with JSON.

or

The second approach certainly is less restrictive in terms of API
usage,

request itself,
