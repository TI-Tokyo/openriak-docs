in the documentation (
<a href="http://riak-users.197444.n3.nabble.com/memory-consumption-td4028674.html">http://riak-users.197444.n3.nabble.com/memory-consumption-td4028674.html</a>).
After that I tried to reduce number of keys stored, changing the
expiry_secs setting from 2 months to 1 month. I expected the memory usage
to drop in half because new keys are put into Riak at a approximately same
rate for last two months and Bitcask stores all keys in memory. But that
didn&#x27;t happen. Memory usage have dropped a little but grew again in a few
days.

So the questions are:
* is there a cheap way to figure out the number of keys stored in a bucket?
* how long does it take to purge old keys from the storage?
* is it possible to see how many keys were expired for the last
minute/hour/day?
* are there some other ways to reduce memory usage I&#x27;m missing except for
adding new servers?

Thanks in advance.

If
yes, check out this discussion:
<a href="http://riak-users.197444.n3.nabble.com/Active-Anti-Entropy-with-Bitcask-Key-Expiry-td4027688.html(might">http://riak-users.197444.n3.nabble.com/Active-Anti-Entropy-with-Bitcask-Key-Expiry-td4027688.html(might</a>
shed more light on the matter).

<blockquote>is there a cheap way to figure out the number of keys stored in a bucket?
</blockquote>No. You can do a streaming list keys, which is less expensive than listing
keys used to be, but I&#x27;m not sure that counts as cheap.

<blockquote>how long does it take to purge old keys from the storage?
</blockquote>This depends on how often Bitcask merges are performed. The expired keys
are actually removed from disk when merging/compaction occurs (though until
then, they will return as not found to client requests).

<blockquote>is it possible to see how many keys were expired for the last
</blockquote>minute/hour/day?
I don&#x27;t think so - Bitcask doesn&#x27;t send any notification to Riak when it
expires the keys, and I don&#x27;t think it keeps any records of its own.
