{field, [
{name, &quot;account&quot;},
{type, integer},
{padding_size, 20}
]},

But I can only query with a 10 digit padded string:

<blockquote><blockquote><blockquote>[l.get_key() for l in client.search(&#x27;answers&#x27;, &#x27;account:%010d&#x27; %
</blockquote></blockquote></blockquote>(12345678)).run()]
[u&#x27;test&#x27;]
<blockquote><blockquote><blockquote>[l.get_key() for l in client.search(&#x27;answers&#x27;, &#x27;account:%d&#x27; %

<blockquote><blockquote><blockquote>[l.get_key() for l in client.search(&#x27;answers&#x27;, &#x27;account:%020d&#x27; %
</blockquote></blockquote></blockquote>(12345678)).run()]
[]

Additionally, I can&#x27;t search for any ints larger than signed 32-bit.

<blockquote><blockquote><blockquote>client.bucket(&#x27;answers&#x27;).new(&#x27;2**31&#x27;, {&#x27;account&#x27;: 2**31}).store()
</blockquote></blockquote></blockquote>&lt;riak.riak_object.RiakObject object at 0x10064ee90&gt;
<blockquote><blockquote><blockquote>client.bucket(&#x27;answers&#x27;).new(&#x27;2**31-1&#x27;, {&#x27;account&#x27;: 2**31-1}).store()
</blockquote></blockquote></blockquote>&lt;riak.riak_object.RiakObject object at 0x10064e550&gt;
<blockquote><blockquote><blockquote>[l.get_key() for l in client.search(&#x27;answers&#x27;, &#x27;account:{%010d TO
</blockquote></blockquote></blockquote>%010d}&#x27; % (0, 2**33)).run()]
[u&#x27;test&#x27;, u&#x27;2%2A%2A31-1&#x27;]

General work-around seems to be to just use the string type and manage
padding on my own [example on a bucket with the default schema]:

<blockquote><blockquote><blockquote>client.bucket(&#x27;questions&#x27;).new(&#x27;2**64&#x27;, {&#x27;account&#x27;: &#x27;%020d&#x27; %
</blockquote></blockquote></blockquote>2**64}).store()
&lt;riak.riak_object.RiakObject object at 0x10064e550&gt;
<blockquote><blockquote><blockquote>client.bucket(&#x27;questions&#x27;).new(&#x27;2**32&#x27;, {&#x27;account&#x27;: &#x27;%020d&#x27; %
