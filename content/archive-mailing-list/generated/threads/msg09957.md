groups to it. This allows you to whitelist specific nodes trying to
talk to the Riak cluster [3].

</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg09981" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Ian Ha</span><time datetime="2013-02-04T07:25:33-08:00">February 4, 2013 at 7:25 AM</time><span class="mailing-list-message__subject">Re: Riak Security on AWS.</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">Yes, you can do that on AWS.

In our case, we just defined a security group called &#x27;riak&#x27;, we set the
inbound restrictions on that group and also tell it to only accept
connections for other EC2 nodes that have the same security group.  On riak
node creation, we give the &#x27;riak&#x27; security group to the node. You also have
the option to define the IP source of the inbound connection (which is what
you are looking to do). This was all done via the AWS console. Just go to
the &quot;Security&quot; tab in the EC2 section of the AWS console.

Hope that helps.
