</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg11582" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Ryan Zezeski</span><time datetime="2013-07-18T06:33:09-07:00">July 18, 2013 at 6:33 AM</time><span class="mailing-list-message__subject">Re: Data population of Yokozuna on key-path in schema?</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">As Eric said, the XML extractor causes the nested elements to become
concatenated by an underscore.  &quot;Extractor&quot; is a Yokozuna term.  It is the
process by which a Riak Object is mapped to a Solr document.  In the case
of a Riak Object whose value is XML the XML is flattened by a)
concatenating nested elements with &#x27;_&#x27; and b) concatenating attributes with
&#x27;@&#x27; (this can be changed if necessary, just ask).  Yokozuna provides a
resource to test how a given object would be extracted.

curl -X PUT -i -h &#x27;content-type: application/xml&#x27; &#x27;<a href="http://host:port/extract&#x27;">http://host:port/extract&#x27;</a>
--data-binary @some.xml

This will return a JSON representation of the field-values extracted from
the object.  You can use a json pretty printer like jsonpp to make it
easier to read.

-Z
