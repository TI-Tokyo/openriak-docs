</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg01635" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Sean Cribbs</span><time datetime="2010-11-27T15:21:42-08:00">November 27, 2010 at 3:21 PM</time><span class="mailing-list-message__subject">Re: Whole cluster times out if one node is gone</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">1) Riak detects node outage the same way any Erlang system does - when a
message fails to deliver, or the heartbeat maintained by epmd fails.  The
default timeout in epmd is 1 minute, which is probably why you&#x27;re seeing it
take 1 minute to be detected.
2) If it takes too long (the vnode is overloaded, perhaps, or is just starting
up as a hint partition) to retrieve from any node, the request can time out.9
3) You could probably configure epmd to timeout sooner, but then you become
more vulnerable to temporary partitions. YMMV
