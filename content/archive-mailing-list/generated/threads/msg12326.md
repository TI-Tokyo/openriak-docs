</blockquote>Riak only accepts ip addresses in the app.config file, but the vm.args &quot;-name&quot; parameter can use either full hostnames or ip addresses.  You can read about the -name parameter at <a href="http://www.erlang.org/doc/reference_manual/distributed.html">http://www.erlang.org/doc/reference_manual/distributed.html</a>.

</blockquote>If you&#x27;ve previously started the node with another &quot;-name&quot; parameter, you will have to do the renaming procedure instead of just changing the &quot;-name&quot; value: <a href="http://docs.basho.com/riak/latest/ops/running/nodes/renaming/">http://docs.basho.com/riak/latest/ops/running/nodes/renaming/</a>.

Another option for your app.config would be to bind everything to &quot;0.0.0.0&quot;, which will make Riak listen on all interfaces.  This combined with using a domain name in the vm.args should prevent you from having to do renames/changing ips in the config files.
If you do this, please consider using a VPC to limit access to the machines.

A good resource to read over is Amazon&#x27;s Riak Whitepaper: <a href="http://media.amazonwebservices.com/AWS_NoSQL_Riak.pdf">http://media.amazonwebservices.com/AWS_NoSQL_Riak.pdf</a>, as it goes through some operation considerations and tuning points that might be useful to you.

Thanks,
Alex
