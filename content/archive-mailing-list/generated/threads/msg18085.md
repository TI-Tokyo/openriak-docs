On Tue, Mar 7, 2017 at 3:58 PM, Luke Bakken &lt;lbak...@basho.com&gt; wrote:
<blockquote>
Hi Daniel,

Thanks for providing all of that information.

You are missing important configuration for riak_kv that can only be
</blockquote></blockquote>provided in an /etc/riak/advanced.config file. Please see the following
document, especially the section to which I link here:
<blockquote><blockquote>
</blockquote></blockquote><a href="http://docs.basho.com/riak/cs/2.1.1/cookbooks/configuration/riak-for-cs/#setting-up-the-proper-riak-backend">http://docs.basho.com/riak/cs/2.1.1/cookbooks/configuration/riak-for-cs/#setting-up-the-proper-riak-backend</a>
<blockquote><blockquote>
[
{riak_kv, [
% NOTE: double-check this path for your environment:
{add_paths, [&quot;/usr/lib/riak-cs/lib/riak_cs-2.1.1/ebin&quot;]},
{storage_backend, riak_cs_kv_multi_backend},
{multi_backend_prefix_list, [{&lt;&lt;&quot;0b:&quot;&gt;&gt;, be_blocks}]},
{multi_backend_default, be_default},
{multi_backend, [
{be_default, riak_kv_eleveldb_backend, [
{data_root, &quot;/opt/data/ecryptfs/riak&quot;}
]},
{be_blocks, riak_kv_eleveldb_backend, [
{data_root, &quot;/opt/data/ecryptfs/riak_blocks&quot;}
]}
]}
]}
].

Your configuration will look like the above. The contents of this file
</blockquote></blockquote>are merged with the contents of /etc/riak/riak.conf to produce the
configuration that Riak uses.
<blockquote><blockquote>
Notice that I chose riak_kv_eleveldb_backend twice because of the
</blockquote></blockquote>discussion you had previously about RAM usage and bitcask (
<a href="http://lists.basho.com/pipermail/riak-users_lists.basho.com/2016-November/018801.html">http://lists.basho.com/pipermail/riak-users_lists.basho.com/2016-November/018801.html</a>
)
<blockquote><blockquote>
In your current configuration, you are not using the expected prefix
</blockquote></blockquote>for the block data. My guess is that on very rare occasions your data
happens to overwrite the manifest for a file. You may also have corrupted
files at this point without noticing it at all.
<blockquote><blockquote>
IMPORTANT: you can&#x27;t switch from your current configuration to this new
</blockquote></blockquote>one without re-saving all of your data.
