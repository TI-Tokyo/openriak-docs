</blockquote></div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg08900" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Anthony Molinaro</span><time datetime="2012-10-12T16:44:42-07:00">October 12, 2012 at 4:44 PM</time><span class="mailing-list-message__subject">Re: Riak connection pool silent disconnection</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">One note about the riak-erlang-client.

Timeouts will cause the client to disconnect.

So if you set a low timeout, it will get disconnected.

The behavior on disconnects can be configured with a couple of options
passed through at create time.

{ auto_reconnect, true } will reconnect if it gets disconnected, but this
can lead to some { error, disconnected } returns depending on the pooler
used.

{ queue_if_disconnected, true } will queue up request if a disconnect happens.

So you might try setting these both and seeing if the disconnect errors turn
into timeouts.  Or try increasing the timeout, you may just have it set too
low.

Now, why a timeout causes a disconnect, I don&#x27;t know, anyone from basho who
works on the riak-erlang-client know?

-Anthony
