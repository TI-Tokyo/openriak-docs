I&#x27;m new to riak, and I am thinking of using riak to store log file / statistics
information from a client application. The main benefit riak could offer here
are its map-reduce/search capabilities.

The client side applications are developed in a variety of languages, but in
the end all requests will be tunneled via a light weight API to our own Erlang
&quot;admin&quot; application.

I&#x27;ve noticed that the riak Erlang API really dispatches requests to the riak
cluster via the gen_tcp module. The logging (insert) rate could be very high,
so what would be neat is if I could embed our Erlang &quot;admin&quot; application
directly into the riak cluster to avoid the IPC hop between the
riak-erlang-client node and the riak node(s).

Now obviously I can fork the code and implement my own way of doing this, but
the question is there an official way to embed your own code directly into a
riak cluster to avoid that extra IPC hop?

Thanks

Matt

</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg03620" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Anthony Molinaro</span><time datetime="2011-06-09T11:49:08-07:00">June 9, 2011 at 11:49 AM</time><span class="mailing-list-message__subject">Re: Erlang API</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">You can, I&#x27;ve done this, you have to modify the /etc/riak/vm.args to
include and start your application (assuming your application has a start/0)
function.

So if you have a foo app, you can add something like

-pa /usr/lib/erlang/lib/foo-0.0.0/ebin
-s foo_app

Then if foo_app.erl has something like

-module(foo_app).

-export([start/0]).

-behaviour(application).
-export([start/2,stop/1]).

start() -&gt;
 application:start (foo).

start(_,_) -&gt;
  foo_sup:start_link().

stop (_) -&gt;
  ok.

That should do it.

-Anthony
