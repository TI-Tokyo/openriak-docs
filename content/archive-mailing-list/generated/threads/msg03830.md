</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg03831" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Andrew Berman</span><time datetime="2011-06-26T15:36:09-07:00">June 26, 2011 at 3:36 PM</time><span class="mailing-list-message__subject">Re: Controlling order of results from link phase</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">I think I found the answer and it is no, I cannot control the sort.  I
found the code here in riak_kv_wm_link_walker.erl:

links(Object) -&gt;
    MDs = riak_object:get_metadatas(Object),
    lists:umerge(
      [ case dict:find(?MD_LINKS, MD) of
            {ok, L} -&gt;
                [ [B,K,T] || {{B,K},T} &lt;- lists:sort(L) ];
            error -&gt; []
        end
        || MD &lt;- MDs ]).

Why run lists:sort?  Shouldn&#x27;t the sort be up to the user after he
gets the actual object?  I don&#x27;t understand why the sort processing is
necessary at the link phase.  Thoughts?

--Andrew
