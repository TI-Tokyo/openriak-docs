should you use when you&#x27;re building your erlang applications.

Nevertheless, as &#x27;basho falks&#x27; suggests it: &quot;The local Erlang client is a

interfaces use the Erlang client internally. The primary client for code
that is not inside of Riak is the Protocol Buffers client:

   - riak-erlang-client on GitHub&lt;<a href="https://github.com/basho/riak-erlang-client">https://github.com/basho/riak-erlang-client</a>&gt;
    &quot;

HTH,
Alin

Yep, that&#x27;s my issue.

My use case is this: I need to fetch all the objects in a secondary index, and
it would be more efficient for me (due to later operations) to fetch the
complete riak objects (i.e. using map_identity) rather than the just values
only (using map_object_value).

However, map_identity returns riak_objects and I gather (but haven&#x27;t dug
deeply) that the whole erlang binary is then stuffed into PB, rather than
individually encoding each object in PB and then decoding into riakc_objs on
the client. At least, that&#x27;s what I assume is going on, more or less.

That may be workable behavior for getting a list of values, but if I&#x27;m getting
the riak objects themselves, it&#x27;s broken. Seems like there needs to be a
mechanism to transport mapreduce results in the same protocol encoding (PB) as
with a get, so that the client gets back a list of riakc_objs.

For the moment, I suppose a map_pb_identity function would suffice, but that
seems like the wrong general solution. But perhaps not.
