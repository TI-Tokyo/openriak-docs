Greeting for this day.

I have successfully inserted data into the riak database using riak-python
client and currently, I&#x27;m using single node configuration. I&#x27;m refering to
<a href="http://riak-python-client.readthedocs.io/en/2.2.0/client.html">http://riak-python-client.readthedocs.io/en/2.2.0/client.html</a> this website for
a tutorial but I&#x27;m having lots of problem in getting the clear solution.

my system configuration is:
OS - Ubuntu Trusty LTS
Python - 2.7.6
Riak KV - 2.1.4

So my question is that now:

Q) I want to see what are all the buckets that are present in my database at
this moment?

<a href="http://riak-python-client.readthedocs.io/en/2.2.0/client.html#riak.client.RiakClient.stream_buckets">http://riak-python-client.readthedocs.io/en/2.2.0/client.html#riak.client.RiakClient.stream_buckets</a>

Q) If I know the name of the buckets then is there any way to retrieve all the
keys that bucket have?

<a href="http://riak-python-client.readthedocs.io/en/2.2.0/client.html#riak.client.RiakClient.get_keys">http://riak-python-client.readthedocs.io/en/2.2.0/client.html#riak.client.RiakClient.get_keys</a>
<a href="http://riak-python-client.readthedocs.io/en/2.2.0/client.html#riak.client.RiakClient.stream_keys">http://riak-python-client.readthedocs.io/en/2.2.0/client.html#riak.client.RiakClient.stream_keys</a>

Q) Is there any possibility by which we can specify the WHERE condition as we
do in SQL?

Yes and no.  The basic .get will return a contents where bucket= and key=

<a href="http://riak-python-client.readthedocs.io/en/2.2.0/client.html#riak.client.RiakClient.get">http://riak-python-client.readthedocs.io/en/2.2.0/client.html#riak.client.RiakClient.get</a>

Beyond that you would need to setup riak search

<a href="http://docs.basho.com/riak/kv/2.2.1/developing/usage/search/">http://docs.basho.com/riak/kv/2.2.1/developing/usage/search/</a>

or secondary indexes

<a href="http://docs.basho.com/riak/kv/2.2.1/using/reference/secondary-indexes/">http://docs.basho.com/riak/kv/2.2.1/using/reference/secondary-indexes/</a>
