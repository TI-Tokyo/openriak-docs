AFAIK, bucket properties are shared via gossip chatter. That is why it is
recommended that you modify the bucket defaults via the config file if you are
going to have a lot of buckets with different params from the default. Bucket
properties and the backends that buckets use are different. Properties play at
the ring/gossip level and backends play at the node level. So, for instance you
can have the same logical &#x27;bucket&#x27; have two different backends on two different
physical nodes, afaik.

-Alexander
</div><ol class="mailing-list-replies"><li class="mailing-list-reply"><details id="msg00952" class="mailing-list-message"><summary><header class="mailing-list-message__header"><span class="mailing-list-message__author">Dan Reverri</span><time datetime="2010-08-25T15:16:06-07:00">August 25, 2010 at 3:16 PM</time><span class="mailing-list-message__subject">Re: propagation of bucket properties to new nodes</span></header></summary><div class="mailing-list-message__content"><div class="mailing-list-message__body">Hi David,

Alexander is correct, bucket properties are gossiped across the cluster. If
the backend property has been set for a bucket, any new nodes added to the
cluster will learn about that backend setting.

A few notes about multi backend:
1. I found a couple of issues with the current multi backend functionality:
Nodes don&#x27;t store data if a backend is not defined on the node:
<a href="https://issues.basho.com/show_bug.cgi?id=670">https://issues.basho.com/show_bug.cgi?id=670</a>

Nodes can&#x27;t find data if the backend property of a bucket is changed after
adding data:
<a href="https://issues.basho.com/show_bug.cgi?id=671">https://issues.basho.com/show_bug.cgi?id=671</a>

Until these issues are fixed I would suggest:
1. Define a consistent &quot;multi_backend&quot; configuration in all nodes
2. Do not change the &quot;backend&quot; property of a bucket once set

I also filed a feature request proposing an alternate method for managing
multiple backends, you can remove this request here:
<a href="https://issues.basho.com/show_bug.cgi?id=672">https://issues.basho.com/show_bug.cgi?id=672</a>

Thanks,
Dan
