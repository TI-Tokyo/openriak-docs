I&#x27;ve set up riaksearch with the following schema document:

{

                {field, [       {name, &quot;_owner&quot;},
                                {required, true},
                                {analyzer_factory, {erlang, text_analyzers,
noop_analyzer_factory}}

                {field, [       {name, &quot;displayName&quot;},

&quot;name_formatted&quot;,
&quot;name_displayName&quot;]},

standard_analyzer_factory}}
                        ]},
                {field, [       {name, &quot;emails_value&quot;},
                                {analyzer_factory, {erlang, text_analyzers,
standard_analyzer_factory}}
                        ]},

                %% Add modification dates
                {field, [       {name, &quot;published&quot;},
                                {aliases, [&quot;updated&quot;]},
                                {type, date}
                        ]}]}.

<blockquote>sudo sudo search-cmd set_schema PortableContacts

<blockquote>sudo search-cmd install PortableContacts
</blockquote>

The error message is indicating that your document contains an
&quot;organizations_name&quot;
field, but that the field doesn&#x27;t exist in your schema. Your options are to
either add a field definition for &quot;organizations_name&quot; to the schema, or add
a dynamic field definition to the end of your schema that catches any fields
that weren&#x27;t previously matched, and maps them to some data type.

The wiki contains more information on dynamic fields (
<a href="http://wiki.basho.com/Riak-Search---Schema.html">http://wiki.basho.com/Riak-Search---Schema.html</a>) but you can also just copy
the entries from the default schema.

Best,
Rusty

Thanks for the quick response!

It turned out I&#x27;d missed the difference between using:

    {field, [{name, &quot;*&quot;}, ...]}

and:

    {dynamic_field, [{name, &quot;*&quot;}, ...]}

Likewise, I had not quite gotten the fact that all fields must
explicitly be covered in the schema definition, not just the subset
you want to do searches on.
